# 邮件助手

把学校 Outlook 邮件自动转发到自己的 QQ 邮箱后，邮件助手读取邮件，并通过用户配置的模型 API 分析分类、简略标题、摘要和待办。用户核对后，可以把事项加入日程或截止事项。

当前 `feature/multiuser` 分支是支持多人登录的网站版本，每位用户连接自己的邮箱和模型服务，邮件、设置和事项按账号隔离。`main` 保留较早的单人版本。

## 仓库怎么读

目录按职责划分，而不是把所有同一种后缀的文件放在一起：

```text
backend/                 后端程序
  cloud.py               登录、账号隔离、网页接口和多人运行入口
  app.py                 每位用户的收信、分析和事项操作
  mail/                  邮件相关功能
    read_model.py        状态更新、邮件摘要列表与按需正文查询
    chat.py              带来源的邮件问答和重要事项提案
    chat_images.py       图片格式、数量与体积验证
    ingest.py            连接邮箱、读取和导入邮件
    analysis.py          分析提示词、结果校验和事项提取
    titles.py            简略标题的读取与校验
    dates.py             邮件日期处理
    original.py          原邮件解析和安全展示
    translation.py       原邮件翻译
  events/                日程与截止事项
    event_join.py        事项加入、重复合并和更新核对
    chat_actions.py      AI 对话事项的验证、逐项确认与自动添加
  core/                  多个功能共用的基础能力
    ai_services.py       模型服务调用
    database.py          邮件数据库与版本升级
    operation_status.py  操作进度和结果状态
    user_errors.py       错误类型和用户提示
  migrations/            旧数据转换
    legacy_titles.py     旧版标题的兼容转换
web/                     浏览器页面
  index.html             主界面内容和结构
  login.html             登录与注册页面
  styles.css             主界面样式
  ui-core.js             页面共享状态与小工具
  settings.js            邮箱、模型和日历设置
  mail-source.js         原邮件与翻译展示
  events.js              重要事项与来源关联
  mailbox.js             邮件列表、搜索、多选和删除撤销
  main.js                账户菜单、初始化与更新轮询
tools/                   本机开发辅助工具
requirements/            公共库与网站服务的依赖清单
tests/                   自动验证功能的测试
docs/                    使用与部署说明
```

程序直接从目录里的模块启动，不再保留根目录的三个启动文件。根目录只保留 `README.md`、`Dockerfile`、`.gitignore` 和 `.dockerignore`：它们分别供 GitHub 展示说明、部署构建、Git 忽略文件和 Docker 忽略文件使用。

如果想逐步理解这个项目，建议按一次操作走过的路径阅读：

1. `web/index.html` 和 `web/mailbox.js`：页面提供什么操作，点击后向后端请求什么。
2. `backend/cloud.py`：请求如何检查登录状态、找到当前用户，并调用功能。
3. `backend/app.py`：收信、分析与事项操作如何串起来。
4. `backend/mail/ingest.py` 和 `backend/mail/analysis.py`：邮件如何进入系统，再变成分析结果。
5. `backend/core/ai_services.py` 和 `backend/core/database.py`：模型如何调用，结果如何保存。
6. `backend/events/event_join.py`：用户确认事项后，如何加入和合并。

文件夹用来归类，文件用来拆分职责。一个功能可以调用其他目录的公共能力，不必把所有代码复制进同一个文件。

## 本机预览多人版

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements/cloud.txt
.venv/bin/python -m tools.preview
```

预览工具只监听本机，并在被 Git 忽略的 `cloud-data/development.secret` 中保存开发密钥。邮箱验证码注册、账号恢复、正式运行、日历订阅和 Railway 部署步骤见 [多人版说明](docs/多人版说明.md)。

生产环境通过 `python -m backend.cloud serve` 启动。仓库中的 Docker 配置已同步更新。下面的命令均在仓库根目录运行。

## 数据存在哪里

GitHub 保存程序和说明，不保存用户邮件、密码、QQ 授权码或 API Key。

多人版运行数据默认在 `cloud-data/`，部署时使用配置的持久化数据目录。每位用户的邮件和设置保存在该目录下各自的数据空间。多人版凭证使用服务器密钥加密；密钥与运行数据需要另外备份，不能依靠 GitHub 恢复。

## 本次可靠性与性能调整

- 临时收信故障保留自动检查开关，延迟后重试；重新开启自动检查沿用上次成功游标，补上间隔期间的新邮件。首次开启仍从当前邮箱位置开始。
- 搜索框旁显示最近检查时间、待分析数量及连接异常状态。
- 邮件删除后可以撤销，已保存的事项与原邮件来源保留；读/未读状态也随恢复保留。
- 页面定时只获取更新标识和运行状态，变化时才获取不含正文的列表。正文按需加载，搜索由服务器覆盖全文，列表分批显示。
- 页面按功能拆分脚本；共用控件的尺寸与样式集中维护。

本机项目已整理到 Documents 下的 `软件开发/timemate`：`app` 是本站代码，`archive` 保留旧版与开发记录，`design` 保存演示。部署不依赖本机绝对路径。

## AI 对话与重要事项

AI 对话可以从文字、最多三张 PNG/JPEG/WebP 图片，或检索到的邮件摘要中整理事项。输入框支持上传和粘贴图片，发送前会重新编码以去除图片附带元数据。图片只在本次请求发送给当前连接的模型服务，不写入本服务数据库或文件；对话保存文件名、识别文字和事项。模型必须支持图片输入，文本模型或不支持的接口会提示切换模型，不会悄悄忽略图片。

页面右上角选择“逐项确认”（默认）或“自动添加”。模式仅决定本次发送的新提案如何处理，不会把先前待确认事项批量加入。自动模式只添加字段完整、无不确定性且未发现相似冲突的事项；缺少日期/年份/结束时间等信息时需要补充后重新整理。明确的考试时段归入日程安排，提交期限归入截止事项，禁止将考试结束时间另造为截止。

每条提案独立保存在当前账号的数据库。添加动作会去重，网络重试也不会重复写入。已有相似事项时要求用户核对，必要时显式选择“另行添加”。加入后沿用重要事项的编辑、完成和移除；日程安排沿用已有日历订阅链接同步（未建立订阅时先留在重要事项）。截止事项沿用站内截止提醒。删除对话会保留已加入事项。

验证：`.venv/bin/python -m unittest discover -s tests`；浏览器回归 `NODE_PATH=<Playwright 安装目录> node tests/test_chat_actions_browser.cjs`，默认使用本机 Chrome。浏览器测试自行创建临时账号数据和模型响应，不访问真实邮箱或模型服务。

## 多 API 连接

AI 服务设置的“我的模型”支持新增、编辑和移除多条 API 连接；相同服务商的不同 Key 独立保存。原有单连接会自动迁移成默认连接，不必重新输入 Key。每条 Key 继续加密保存，列表和设置接口不会返回原值；修改已有连接时 Key 留空会保留该连接的 Key，新建连接必须填写 Key。

添加的第一个模型自动用于邮件分析。之后可在服务的编辑弹窗中勾选“邮件自动分析”，并选择具体型号；主列表不再单独显示此选项。AI 对话输入区的模型菜单可单独切换连接，不改变邮件自动分析默认值；所选连接随对话保存，刷新后恢复。移除非默认连接会同时清除其已保存 Key；默认连接需先改用另一条才能移除。

事项添加菜单仅在展开时解释两种模式：逐项确认由用户逐条添加，自动添加直接加入明确事项；信息不全或相似冲突仍需确认。
